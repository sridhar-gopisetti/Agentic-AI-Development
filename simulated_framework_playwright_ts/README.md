## Architecture Decisions

### Why `BasePage` instead of raw `Page`?
`BasePage` wraps Playwright's `Page` with a `waitForVisible` / `waitForHidden` guard layer and an abstract `validate()` contract — the TypeScript equivalent of Java's `LoadablePage`. This enforces consistent element-ready checks without `waitForTimeout()`.

### Why custom fixtures in `src/fixtures/index.ts`?
Playwright fixtures provide constructor-injection of typed page objects into every `test()` function, eliminating manual `new LoginPage(page)` boilerplate and ensuring every test starts with a clean, correctly-scoped instance.

### Why `test.step()` on every manual step?
`test.step()` maps directly to `report.logStep(TestStep.builder()...)` in the Java framework. It produces structured HTML report sections and satisfies the `UNI-005` traceability rule (1 manual step → 1 code block → 1 comment).
